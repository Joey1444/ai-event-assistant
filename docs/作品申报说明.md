# 作品申报说明

## 1. 作品名称

**「文枢」—— 国际中文教育文化活动智能策划体（Culture Event Planner）**

> 备选名：策文阁（国际中文教育文化活动策划智能体）/ 语墨（面向国际中文教育的文化传播策划智能体）

## 2. 作品简介（摘要）

**功能定位**：面向国际中文教育机构的文化活动智能策划体。文化活动是国际中文教育的重要组成部分——它把语言教学延伸到真实的文化体验与传播场景，是孔子学院与中文教学机构落实「文化传播」使命的主要载体。作品以「AI 提议、人类决定」为原则，将一场文化活动从需求分析到最终审批的全流程，交由多个分工明确的 AI 智能体协同完成，帮助机构把文化推广做得更专业、更可控、更可复制。

**使用对象**：孔子学院、中文教学机构的文化活动组织者、一线教师与行政人员。他们大多具备语言教学与文化素养，但不一定熟悉「方案—预算—文案—海报—执行—评估」的完整策划链路，也缺少专职的策划、财务、设计分工。

**应用场景**：中秋、春节等传统节日的文化体验活动，以及汉语角、文化工坊、招生宣传等日常文化传播场景。首个落地案例为莫伊大学孔子学院 2026 年中秋活动策划。

**核心功能**：① 多智能体流水线（项目经理、资料调研、策划师、评审、事实核查、详细方案、预算、文案、海报、质检）分工协作；② 两道人工关卡（选方向、最终审批），AI 只提议、不拍板；③ 事实账本反幻觉机制，外部事实带来源、可追溯、可人工核验；④ AI 生成内容全部可修改并保留版本；⑤ 文生图海报与图生图迭代修改。

**创新点**：一是把文化活动策划从「通用 AI 问答」升级为「结构化多智能体流水线」，贴合文化活动的专业分工；二是以「事实账本」把「不编造」落成可执行机制——凡外部事实必有来源、无来源显式标注、冲突保留双方原文；三是「人机协同」边界清晰，AI 只做专业生产、人类掌握关键决策，契合国际中文教育对文化传播「真实、准确、负责任」的要求。

**推广价值**：把「办一场高质量文化活动」的门槛从「需要一支专业策划团队」降到「一个人 + 一台电脑」，让海外中文教学机构在人手与经费有限时也能稳定输出规范、可追溯、可复用的文化活动方案，更好地履行文化传播与语言教学融合的使命。

## 3. 应用场景与问题任务

**归类说明**：本作品归入「教学管理与学习服务」类，并建议明确为其中的「文化活动策划与管理」子项。理由：孔子学院与中文教学机构以「语言教学 + 文化传播」为双主线，文化活动（节日体验、文化工坊、汉语角、招生宣传）是文化教学与学习服务的主要落地形式。因此，文化活动的策划与管理本质上是机构「学习服务」的组织与运营，既非课堂教学管理，也非评价反馈或教科研，归入「教学管理与学习服务」准确、贴切。

**希望解决的具体问题**：

1. **策划专业能力不足**。一线教师以语言教学为主，不熟悉「方案—预算—文案—海报—执行—评估」完整链路，文化活动常停留在「有想法」而难以落地为可执行方案。

2. **专业分工缺失**。预算测算、宣传文案、海报设计、风险与评估需要不同技能，机构内往往无人专职承担，导致活动质量参差、周期拉长。

3. **通用 AI 的幻觉与文化失真风险**。直接让通用大模型写文化方案，易编造不存在的场地、价格、日期与文化细节，甚至造成文化误读——文化传播一旦失真，损害的是机构的专业公信力。

4. **活动经验难以沉淀**。成功经验散落在个人记忆中，无法形成可追溯、可复用的机构知识资产，人员流动即归零。

针对以上问题，本智能体提供一条结构化、带人工把关与事实核验的活动策划流水线：用户只需填写简报，AI 完成专业分工的「重活」，关键事实必须可追溯、关键决策必须由人点击，在「降低门槛」与「守住真实」之间取得平衡。

## 4. AI 介入、人机协同与创新机制

### 4.1 总体思路：从「单一问答」到「多智能体协作」

本作品的核心理念不是「把需求丢给一个大模型、让它一次性生成答案」，而是把一次完整的文化活动策划拆解为一条**多智能体协作流水线**。系统内部署了项目经理、资料调研、策划师、评审、事实核查、详细方案策划师、预算规划师、文案策划师、海报设计师、海报视觉设计、质检共 11 个角色化智能体，每个智能体只承担一个环节的专业产出。每个智能体的提示词都遵循「角色 + 任务 + 输出约束 + 规则」的统一结构，明确它「是谁、要做什么、输出什么格式、不能做什么」，静态指令与动态输入分离以节省开销。

选择多智能体而非单一问答，出于三点考量：其一，**职责单一更容易写好、也更好校验**——一个只负责打分的评审智能体，比一个什么都做的全能模型输出更稳定、更易验证；其二，**分工使中间结果可被下游引用与纠正**——调研产出的事实可被策划、预算、文案反复引用，事实核查还能反过来对它们纠错；其三，**可独立替换与升级**——换掉文案智能体的提示词或模型，不影响流水线其它环节。

关键在于，每个智能体的输出都不会停留在聊天文本里，而是被解析为结构化数据并**落库**，成为下一个智能体的输入：资料调研产出的事实账本，既会成为策划师设计方案的依据，也会成为事实核查环节的核验对象。这种「上游产出即下游输入」的编排，让多个智能体各司其职、层层校验，而非靠一个模型的一次生成包打天下。

围绕这条流水线，本作品具备智能体系统的三个典型属性：**多智能体协作**（11 个角色分工、顺序推进）、**工具调用**（联网检索 Tavily 与文生图 DashScope 两项外部工具能力）、**状态记忆**（所有产出与决定持久化到数据库，带版本与时间戳可追溯）。而贯穿始终的是「**AI 提议，人类决定**」的 Human-in-the-loop 人机协同边界。

### 4.2 设计搭建流程：四层分离与统一网关

技术上，本作品采用「智能体四层分离」的架构，把每个智能体的职责拆到四个层面：

1. **提示词纯函数层**（`lib/agents/<name>.ts`）：每个智能体只写「提示词 + 结果解析」的纯函数，输入结构化数据 → 调用 AI → 输出经类型与取值范围校验的结构化数据，不碰数据库、不碰界面。
2. **服务端编排层**（`lib/agents/actions.ts`）：负责「读哪些表 → 调哪个智能体 → 写哪张表」的落库编排，是流水线串起来的实际执行者。
3. **元数据注册表层**（`lib/agents/registry.ts`）：Agent 清单、角色、输入输出的单一事实来源。
4. **面板层**（`components/agents/<Name>Panel.tsx`）：客户端组件，只负责「按钮 + 调 action + 展示结果」。

所有模型调用统一走 `lib/ai/provider.ts` 这一**唯一入口**：文本生成 `generateText()`、文生图 `generateImage()`、联网检索 Tavily 封装。业务代码与智能体一律不得直接访问模型端点，换模型只改配置，实现 Provider 无关。错误统一分类为网络、超时、截断等可读提示；模型输出的 JSON 做防御性解析，畸形输入给出可读错误而非页面崩溃。

两项工具能力补齐了纯文本模型的两块短板：联网检索（Tavily）让智能体获取**实时的、可溯源的**外部信息，避免训练数据过时导致的价格、场地、日期失真；文生图（DashScope）让系统不仅能「写」文案，还能「画」出可直接使用的海报图片，并支持基于上一张图的图生图迭代修改。

### 4.3 核心功能与一条完整交互任务流程

以「策划一场中秋节文化活动」为例，用户走完一条完整的流水线：

1. **填简报**：用户新建项目，填写活动名称、机构、日期、人数、预算、地点、目标人群等基础信息。
2. **项目经理体检**：AI 对简报做信息体检，指出「日期、预算缺失」等阻塞项与次要提醒，用户补充后继续。
3. **资料调研**：AI 联网检索机构与场地等真实资料，产出入库的研究条目与事实账本，每条事实带来源链接。
4. **策划方案**：AI 生成 2~4 个方向不同的候选方案（如「低门槛游园会」「沉浸式文化工坊」）。
5. **AI 评审**：评审智能体对候选方案做 8 维评分与优缺点、风险分析，给出推荐。
6. **关卡 1 选方向**：用户在多个方案中**点击**选定一个方向，系统绝不自动选。
7. **事实核验**：AI 抽取选中方案中的外部事实，逐一判定 FACT / USER_PROVIDED / ASSUMPTION / UNKNOWN / CONFLICT，用户对存疑事实点击「确认 / 驳回 / 补充说明」。
8. **并行产出**：基于选中方案依次生成 15 章节详细方案、10 类预算、多用途宣传文案、海报文案，并调用文生图生成海报图片（支持历史版本与图生图迭代修改）。
9. **发布前质检**：QA 智能体核对日期、地点、预算等跨模块一致性，输出 PASS / WARNING / BLOCK。
10. **关卡 2 审批**：用户点击「批准 / 驳回 / 要求修改」，流程结束，产出完整策划方案。

每一步的产物都可编辑、重新生成，并写入数据库对应表，带版本号与时间戳，重新生成时版本递增、不覆盖旧版。这正是智能体「状态记忆」的体现——系统记住的不只是最终答案，而是全过程每一步、每一个版本，可随时回看与对比。

### 4.4 人机协同模式与创新之处

**人机协同模式**：AI 承担「重、专、多」的生成工作——方案、预算、文案、海报、质检；人类承担「真、对、拍板」的决策工作——补充关键信息、选择方向、核验事实、最终审批。二者通过「数据落库 + 人工关卡」衔接，边界清晰，AI 全程只生成候选与建议，不替人做任何关键决定。这种边界设计的价值在于：它既把「办一场高质量活动」的门槛从「需要一支专业策划团队」降到「一个人 + 一台电脑」，又用架构守住「AI 不能替人拍板、不能编造事实」的底线，让不熟悉策划流程的一线教师也能放心使用。

本作品的创新点有三：

1. **事实账本反幻觉机制**：把「不编造」从一句口号变成一套可执行、可验证的机制。外部事实（场地、日期、价格、规定）必须有来源；无来源显式标注 UNKNOWN、推测标 ASSUMPTION；出现冲突时保留双方原文而非只给结论；用户提供或人工核验通过的事实标 USER_PROVIDED；人工核验的结果只能由真人写入，AI 绝不代真人标注「已核验」。事实在「unverified → ai_checked → human_verified / rejected」的状态机上流转，AI 的输出只能停在 ai_checked，human_verified 只能来自真人点击。
2. **双重人工关卡**：在流水线中嵌入「选方向」与「最终审批」两道必须由真人点击的关卡，从架构上保证 AI 不能替人拍板，把「人主导、AI 辅助」从原则固化为不可绕过的流程节点。
3. **全流程可追溯**：每个 AI 结果带版本号与时间戳，重新生成不覆盖旧版；每个人的决定（选方向、核验、审批）都落库并成为后续步骤的输入，可回看、可复现、可审计。

## 5. 知识图谱或语料库使用情况说明

本作品**未接入**国际中文教育知识图谱，也**未预置**固定语料库，采用「联网实时检索 + 项目内事实账本」方案，特此如实说明。

**一、未使用知识图谱的理由**。文化活动策划依赖的场地、价格、日期、机构规定、文化背景等信息具有强时效性：报价会变、开放日期会变、规章会更新，预置知识图谱或语料库一旦形成即开始「过期」。因此本作品选择以 Tavily 联网检索获取实时公开资料，换取信息的时效性与可核验性——每条事实均带来源链接，评委与用户可随时点击核验，这是静态语料库难以替代的。代价是需要联网环境。

**二、事实账本作为可追溯的结构化知识管理机制**。虽未用知识图谱，但本作品以「事实账本」承担「把知识管起来」的职责：资料调研智能体将检索结果抽取为「研究条目 + 事实」两类结构化数据落库；每条事实带来源名称与链接，并带 FACT / USER_PROVIDED / ASSUMPTION / UNKNOWN / CONFLICT 五类状态标记；无来源显式标 UNKNOWN、推测标 ASSUMPTION、冲突保留双方原文；人工核验后的结果只能由真人写入，绝不把 AI 推断标成「已核验」。这构成一套可追溯、可核验、可沉淀的结构化事实管理机制——它不预设领域知识，但保证进入方案的知识都有出处、有状态、有人把关，体现了对「知识真实性与可追溯性」的更严格要求。

**三、接入国际中文教育知识图谱的规划**。本作品架构已为此预留路径：事实账本本身即「实体—属性—来源」的最小单元，未来可将账本事实映射到国际中文教育知识图谱（如节令习俗、文化专题、机构库）作为节点，形成「实时检索补充时效信息 + 知识图谱提供稳定领域知识」的双源融合；账本沉淀的历史事实亦可反哺机构自有小规模领域知识库。当前以「诚实标注 UNKNOWN + 来源可追溯」为底线，为后续接入保留开放接口。

## 6. 验证情况、效果证据与价值判断

**验证情况：尚未开展面向真实用户的正式验证。**本作品目前处于「MVP 核心功能完成」阶段，如实说明如下。

**（一）作品完成情况**

以下内容均已实现，可在本地完整跑通「创建项目 → 全流程 → 两道关卡 → 审批」：

- **数据模型**：Prisma + SQLite 完整数据模型，覆盖简报、分析、研究条目、事实账本、方案、评审、决策、预算、文案、海报、海报图片、质检、审批等全部环节，每类产物独立成表并带版本与时间戳。
- **全部智能体**：项目经理、资料调研、策划师、评审、事实核查、详细方案、预算、文案、海报、海报视觉设计、质检共 11 个智能体，提示词、解析、落库全部实现。
- **两道人工关卡**：选方向与最终审批均可真实点击，决定落库并成为后续输入。
- **全部面板 UI**：每个智能体都有独立可交互面板，结果可编辑、可重新生成、可查看历史版本。
- **AI 网关**：文本生成、文生图、联网检索三类模型能力统一接入，含错误分类与防御性解析。
- **模型配置界面**：可在网页表单配置文本 / 文生图模型的地址、模型名与密钥，保存后立即生效，密钥只显示掩码。
- **一键安装 / 启动脚本**：双击即可完成首次安装与日常启动，无需编程背景。

总体而言，作品已从「数据层 → 智能体层 → 关卡 → 界面 → 网关 → 配置 → 部署」形成完整闭环，且本地可复现，具备对外演示与小范围试用的基础。

**（二）自检证据**

- **验证闸门全绿**：项目内置 `verify.sh` 验证闸门（TypeScript 类型检查 + ESLint + 生产构建）三连通过，无类型错误、无 lint 违规、生产构建成功。
- **全新环境实测**：以「全新环境」方式实测首次安装脚本，依赖安装、数据库初始化、配置引导完整跑通。
- **反幻觉规则可对应到实现**：提示词中的反幻觉规则、事实状态机、防御性 JSON 解析均有对应代码实现，可在成果展示中逐一对照。

**（三）存在的不足**

1. 尚未建立自动化测试体系（单元 / 集成 / 端到端测试在待办中）；
2. 尚未开展真实用户试用，缺乏效果数据（如事实准确率、方案可用性的量化指标）；
3. 联网调研依赖外部搜索服务与网络环境，离线场景下研究库与事实账本为空。

**（四）后续验证计划**

1. 补测试体系：Provider 层、各智能体解析器、智能体 → 落库集成、端到端全流程；
2. 邀请孔子学院一线教师小范围试用，收集「方案可用性、事实准确率、操作易用性」三方面反馈；
3. 针对试用反馈迭代提示词与交互，再行复测。

**价值判断**：本作品的价值不在于「生成一篇漂亮文案」，而在于把「AI 辅助活动策划」这个高频、真实、且有明确质量风险（幻觉）的任务，落成一套**可追溯、有人把关、可复制**的工程方案，具备在海外中文教学机构推广的实用基础。

- 本项目以**本地运行 + 私有仓库**方式发布：用户下载解压后，双击「首次安装脚本」与「启动脚本」即可使用，无需编程背景，也无需自行配置依赖。
- 环境要求：**Node.js 20.9 及以上**。
- 模型可换：文本模型默认 DeepSeek，文生图默认通义万相，均可在配置界面更换为其它兼容服务；项目本身不持有任何模型密钥，密钥由用户自备，绝不写入前端或提交。
