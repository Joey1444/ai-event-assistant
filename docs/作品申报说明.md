# 作品申报说明

## 1. 作品名称

AI 文化活动策划智能体（Culture Event Planner）

## 2. 作品简介（摘要）

**功能定位**：面向国际中文教育机构（孔子学院、中文学校）的文化活动策划智能体。用户填写一份活动简报（名称、机构、日期、人数、预算、地点、人群等），智能体即调用多个 AI 智能体分工协作，依次完成需求分析、联网调研、方案设计、评审、事实核验、详细方案、预算、宣传文案、海报、发布前质检，最终由用户本人完成两处关键审批，输出一套可直接落地的活动策划方案。

**使用对象**：孔子学院 / 中文教学机构的文化活动组织者、一线教师与行政人员——他们往往不熟悉大型活动策划流程，也不具备文案、预算、海报设计等专业分工，需要一个「懂策划、不瞎编、听人话」的 AI 助手。

**应用场景**：中秋、春节等传统节日文化活动，以及汉语角、文化体验、招生宣传等机构日常活动。

**核心功能**：① 多智能体流水线（项目经理、资料调研、策划师、评审、事实核查、详细方案、预算、文案、海报、质检）；② 两道「人工关卡」（选方向、最终审批），AI 只提议、不拍板；③ 事实账本反幻觉机制（联网调研的事实带来源、可追溯、可人工核验）；④ AI 生成的全部内容均可人工修改并保留历史版本；⑤ 文生图海报生成与图生图迭代修改。

**创新点**：一是「AI 提议 + 人类决定」的人机协同范式——把 AI 定位为参谋而非决策者，从机制上守住「人主导、AI 辅助」的边界；二是「事实账本」反幻觉机制——凡外部事实（场地、日期、价格、规定）必须有来源，无来源一律标 UNKNOWN/ASSUMPTION，绝不凭常识编造，并由真人核验后升级为可信事实；三是「全流程可追溯」——每个 AI 结果带版本与时间戳，每个审批决定落库并成为后续输入。

**推广价值**：把「办一场高质量文化活动」的门槛从「需要一支专业策划团队」降到「一个人 + 一台电脑」，尤其适合人手有限、经费有限的海外中文教学机构，可复制到各类文化活动场景。

## 3. 应用场景与问题任务

本智能体面向**教学管理与学习服务**这一类真实任务中的「文化活动策划与管理」。

**要解决的具体问题**：海外中文教学机构（以孔子学院为代表）在举办文化活动时普遍面临三类困境：

1. **策划经验不足**：一线教师多为语言教学背景，不熟悉「方案—预算—文案—海报—执行表—评估」的完整策划链路，活动常常停留在「有个想法」而难以落地为可执行方案。
2. **专业分工缺失**：预算测算、宣传文案、海报设计、风险与评估等需要不同技能，机构内往往无人专职承担，导致活动质量参差、周期拉长。
3. **通用 AI 的「幻觉」风险**：直接让通用大模型写活动方案，容易编造不存在的场地、价格、日期、规定，把假设当成事实，可能造成实际执行中的误导甚至事故。

针对以上问题，本智能体提供一条**结构化的、带人工把关与事实核验的活动策划流水线**：用户只需填写简报，AI 完成专业分工的「重活」，但关键事实必须可追溯、关键决策必须由人点击，从而在「降低门槛」和「守住真实」之间取得平衡。

## 4. AI 介入、人机协同与创新机制

### 4.1 总体思路

核心设计哲学是「**AI 提议，人类决定**」。系统把一次活动策划拆解成一条**多智能体流水线**：每个智能体只负责一个环节的「专业产出」，产出物落库并成为下一步的输入；流水线中嵌入两道**必须由真人点击**的关卡。AI 全程只生成候选与建议，不替人做任何关键决策。

### 4.2 设计搭建流程

流水线顺序（以智能体注册表为准）：

```
简报 → 项目经理 → 资料调研 → 策划师 → 评审 → 🧑关卡1 选方向
     → 事实核查 → 详细方案 → 预算/文案/海报 → 海报视觉设计 → 质检 → 🧑关卡2 审批
```

- **项目经理**：给简报做信息体检，指出「会阻塞策划的缺失项」与次要提醒。
- **资料调研**：联网检索（Tavily）真实资料，产出入库的「研究条目 + 事实」。
- **策划师**：生成 2~4 个方向不同的候选方案。
- **评审**：对候选方案做 8 维打分与优缺点分析，给出推荐。
- **关卡 1（人工）**：用户在多个方案中**点击选择**一个方向（或全部驳回），系统绝不自动选。
- **事实核查**：针对选中方案，抽取所有「外部事实」（场地、日期、价格、规定等），逐一判定 FACT / ASSUMPTION / UNKNOWN / CONFLICT，并标记哪些需要人工核验。
- **详细方案 / 预算 / 文案 / 海报**：基于选中方案产出正式方案（15 章节）、10 类预算、中英文案、海报文案与文生图海报。
- **质检**：发布前最后一道 AI 检查，输出 PASS / WARNING / BLOCK。
- **关卡 2（人工）**：用户点击「批准 / 驳回 / 要求修改」。

### 4.3 核心功能与交互流程

**一条完整的用户交互任务流程**（以「策划一场中秋节文化活动」为例）：

1. 用户新建项目，填写简报（名称、机构、日期、人数、预算、地点、目标人群）。
2. 点击「项目经理分析」，AI 提示「日期/预算缺失」等阻塞项，用户补充后继续。
3. 点击「资料调研」，AI 联网检索机构与场地资料，填充研究库与事实账本（每条带来源链接）。
4. 点击「出活动方案」，AI 生成 2~4 个方向不同的方案（如「低门槛游园会」「沉浸式文化工坊」）。
5. 点击「评审」，AI 给各方案打分与推荐。
6. **关卡 1**：用户在多个方案中点击选中一个方向。
7. 点击「事实核验」，AI 抽出选中方案的外部事实，标注需人工核验的条目；用户对存疑事实点击「确认 / 驳回」。
8. 依次点击生成「详细方案、预算、文案、海报」，各环节产物均可编辑、重新生成、保留版本。
9. 点击「发布前检查」，AI 核对日期/地点/预算等跨模块一致性。
10. **关卡 2**：用户点击「批准」，流程结束，产出完整策划方案。

### 4.4 人机协同模式与创新之处

**人机协同模式**：AI 承担「重、专、多」的生成工作（方案、预算、文案、海报、质检），人类承担「真、对、拍板」的决策工作（补充关键信息、选方向、核验事实、最终审批）。二者通过「数据落库 + 人工关卡」衔接，边界清晰。

**创新之处**：
1. **事实账本反幻觉**：把「不编造」从一句口号变成一套可执行的机制——外部事实必须有来源，无来源显式标注，冲突保留双方原文，人工核验结果只能由真人写入。
2. **双重人工关卡**：从架构上保证「AI 不能替人做最终决定」。
3. **全流程可追溯**：每个 AI 结果带版本与时间戳，每个决定落库并成为后续输入，可回看、可复现。

## 5. 知识图谱或语料库使用情况说明

本作品**未使用**国际中文教育知识图谱或预置语料库，采用「**联网实时检索 + 项目内事实账本**」的方案，理由与可追溯性说明如下：

- **调用方式**：资料调研智能体通过 Tavily 搜索接口实时检索互联网公开资料（机构信息、场地、文化背景、价格规定等），提取为「研究条目」与「事实」两类结构化数据。
- **使用场景**：在策划、事实核验、预算、文案、海报等需要「真实外部信息」的环节，供下游智能体引用。
- **可追溯性**：每条事实都带 `source`（来源名称）与 `sourceUrl`（来源链接），并带状态标记（FACT/ASSUMPTION/UNKNOWN/CONFLICT）；人工核验后的结果单独落库，绝不把 AI 推断标成「已核验」。成果展示中可点开任意事实查看其来源链接，满足资源使用的可追溯要求。

采用实时检索而非固定语料库，是为了避免「训练数据过时」导致的价格、场地、日期等信息失真，代价是需要联网环境。

## 6. 验证情况、效果证据与价值判断

**验证情况：尚未开展面向真实用户的正式验证**。本作品目前处于「MVP 核心功能完成」阶段，如实说明如下：

- **作品完成情况**：数据模型（Prisma + SQLite）、全部智能体（项目经理 / 资料调研 / 策划师 / 评审 / 事实核查 / 详细方案 / 预算 / 文案 / 海报 / 海报视觉设计 / 质检）、两道人工关卡、全部面板 UI、AI 网关（文本 + 文生图 + 联网检索）、模型配置界面、一键安装/启动脚本均已实现，本地可完整跑通「创建项目 → 全流程 → 两道关卡 → 审批」。
- **自检情况**：通过项目验证闸门 `verify.sh`（TypeScript 类型检查 + ESLint + 生产构建）三连全绿；并以「全新环境」方式实测了首次安装脚本（依赖安装、数据库初始化、配置引导）完整跑通。
- **存在的不足**：① 尚未建立自动化测试（单元测试 / 集成测试 / 端到端测试在待办中）；② 尚未开展真实用户试用，缺乏效果数据；③ 联网调研依赖外部搜索服务与网络环境。
- **后续验证计划**：① 补测试体系（Provider 层、解析器、agent→落库集成、E2E）；② 邀请孔子学院教师进行小范围试用，收集「方案可用性、事实准确率、操作易用性」三方面反馈；③ 针对试用反馈迭代提示词与交互。

**价值判断**：本作品的价值不在于「生成一篇漂亮文案」，而在于把「AI 辅助活动策划」这个高频、真实、且有明确质量风险（幻觉）的任务，落成一套**可追溯、有人把关、可复制**的工程方案，具备在海外中文教学机构推广的实用基础。
