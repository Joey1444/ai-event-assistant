# 作品申报说明

## 1. 作品名称

**「文枢」—— 海外中文教学文化活动一人策划智能体**

> 副标题：从需求到审批，一名教师 + 一台电脑即可完成全流程

## 2. 作品简介（摘要）

**功能定位**：「文枢」是一款面向海外国际中文教育场景的文化活动智能策划体。文化活动是孔子学院与中文教学机构履行「文化传播」使命的主要载体，但一线教师普遍不具备完整的策划能力。作品以「AI 提议、人类决定」为原则，把一场文化活动从需求分析、方案设计、预算测算、文案海报到发布前审批的全流程，交给 11 个分工明确的 AI 智能体协同完成，让普通教师无需专业团队即可交付规范、可追溯、可复用的活动方案。

**使用对象**：孔子学院及海外中文教学机构的新任教师、活动组织者与行政人员。他们大多具备语言教学能力与文化素养，但缺乏「方案—预算—文案—海报—执行—评估」的完整策划经验，机构内也几乎没有专职的策划、财务、设计岗位。

**应用场景**：中秋、春节等传统节日文化体验活动，以及汉语角、文化工坊、招生宣传等日常场景。试用场景为莫伊大学孔子学院 2026 年中秋活动策划。

**核心功能**：① 多智能体流水线，覆盖项目经理、资料调研、策划、评审、事实核查、详细方案、预算、文案、海报文案、海报视觉、发布质检 11 个专业环节；② 两道人工关卡（选方向、最终审批），AI 只产出候选与建议，拍板权完全在人；③ 事实账本反幻觉机制——外部事实必须带来源，无来源显式标注 UNKNOWN，推测标 ASSUMPTION，冲突保留双方原文，人工核验结果只能由真人写入；④ 所有 AI 产出可编辑、可重新生成，版本递增不覆盖旧版，全过程可回看可审计；⑤ 海报文案与文生图在同一流程内衔接，支持基于上一版图片的图生图迭代修改，无需跨工具手动搬运提示词。

**创新点**：一是把文化活动策划从「通用 AI 问答」升级为结构化多智能体流水线，每个智能体职责单一、输出可校验、上游产出自动成为下游输入；二是以「事实账本」将「不编造」从口号落成可执行机制——凡外部事实必有出处，无出处即显式标记，AI 绝不代真人标注「已核验」；三是「人机协同」边界从架构上固化，AI 只做专业生产，人类掌握关键决策，契合国际中文教育对文化传播「真实、准确、负责任」的要求。

**推广价值**：把「办一场高质量文化活动」的门槛从「需要一支专业策划团队」降到「一名教师 + 一台电脑」。海外中文教学机构普遍人手少、经费紧、教师流动性大，本作品让活动方案不再依赖个别老教师的个人经验，而是沉淀为机构可追溯、可复用、可交接的知识资产，使文化传播使命在有限条件下也能稳定落地。

## 3. 应用场景与问题任务

**任务归类**：本作品归入「教学管理与学习服务」类别，具体对应其中的文化活动策划与管理。理由：孔子学院与海外中文教学机构以「语言教学 + 文化传播」为双主线，节日体验、文化工坊、汉语角、招生宣传等文化活动是文化教学与学习服务的主要落地形式。活动的策划、组织与运营本质上属于机构「学习服务」的管理范畴，既非课堂教学管理，也非评价反馈或教科研。

**真实用户画像**：被派往海外的中文教师，以本作品试用场景为例——莫伊大学孔子学院的志愿者教师——典型处境是：语言学出身，未受过活动策划训练；孤身赴任，身边没有策划、财务、设计分工；预算有限且需走当地采购流程；活动面对当地学生与社区，对文化细节、场地条件、价格水平均不熟悉；同时还需兼顾日常教学，可用在活动策划上的时间极为有限。

**希望解决的具体问题**：

1. **策划专业能力断层**。一线教师能教中文、懂文化，但不熟悉「需求分析—方案设计—预算测算—文案撰写—海报制作—风险评估—审批汇报」的完整链路，活动往往停留在「有想法」阶段，落不到可执行、可审批的方案文档。

2. **工具链断裂，上下文靠人脑搬运**。现实中教师策划一场活动，通常要在 ChatGPT 写方案、Excel 算预算、Canva 或 Midjourney 做海报、Word 写文案之间来回切换，每个工具独立工作，教师需手动把上一步的结果复制粘贴到下一步，稍有遗漏就出现方案与预算对不上、文案与海报不一致，更不用说海报提示词需反复调试，效率极低。

3. **通用 AI 的幻觉与文化失真风险**。直接让通用大模型写文化活动方案，极易编造不存在的场地、不符合当地实际的价格、错误的日期与文化细节。文化传播一旦失真，损害的不是方案质量，而是机构的专业公信力——尤其在跨文化场景下，一个事实错误可能被放大为文化误解。

4. **经验无法沉淀，人走经验走**。成功的活动经验散落在老教师的个人记忆和聊天记录里，没有结构化记录。人员轮换后，新任教师从零开始摸索，机构的活动质量随人员流动大幅波动。

针对以上问题，本智能体提供一条结构化、带人工把关与事实核验的活动策划流水线：用户只需填写一份简报，AI 完成所有专业分工的「重活」；关键事实必须可追溯、关键决策必须由人点击；全部环节在同一平台内完成，数据自动在步骤间流转，无需跨工具搬运。

## 4. AI 介入、人机协同与创新机制

### 4.1 总体思路：从「一次问答」到「多智能体协作流水线」

本作品的核心理念不是「把需求丢给一个大模型、让它一次性生成答案」，而是把一次完整的文化活动策划拆解为一条多智能体协作流水线。系统内部署了 11 个角色化智能体：项目经理（信息体检）、资料调研（联网检索）、策划师（方案生成）、评审（8 维评分）、事实核查（外部事实核验）、详细方案策划师、预算规划师、文案策划师、海报文案师、海报视觉设计师（文生图与图生图迭代）、发布质检。每个智能体只承担一个环节的专业产出，提示词遵循「角色 + 任务 + 输出约束 + 规则」的统一结构，静态指令与动态输入分离。

选择多智能体而非单一问答，出于三点考量：其一，职责单一使输出更稳定、更易校验；其二，上游产出自动成为下游输入，调研事实可被策划、预算、文案反复引用，事实核查还能反向纠错；其三，各智能体可独立替换升级，互不影响。

关键在于，每个智能体的输出不停留在聊天文本里，而是被解析为结构化数据并落库，自动成为下一个智能体的输入，让多个智能体各司其职、层层校验。本作品具备多智能体协作、工具调用（联网检索 Tavily、文生图 DashScope）、状态记忆（产出与决定持久化、带版本与时间戳）三项智能体系统属性，贯穿始终的是「AI 提议，人类决定」的人机协同边界。

### 4.2 设计搭建流程：四层分离与统一 AI 网关

技术上采用「智能体四层分离」架构，把每个智能体拆到四个层面：

1. **提示词纯函数层**：只写「提示词 + 结果解析」纯函数，输入结构化数据 → 调用 AI → 输出经校验的结构化数据，不碰数据库、不碰界面。
2. **服务端编排层**：负责「读哪些表 → 调哪个智能体 → 写哪张表」的落库编排，是流水线串联的实际执行者。
3. **元数据注册表层**：Agent 清单、角色、输入输出的单一事实来源，新增或调整智能体只改此处。
4. **面板层**：客户端组件，只负责「按钮 + 调 action + 展示结果」，加载态与错误态清晰。

所有模型调用统一走一个 AI 网关：文本生成、文生图、联网检索均经此封装，业务代码与智能体一律不得直接访问模型端点，换模型只改配置，实现 Provider 无关。错误统一分类为网络、超时、截断等可读提示；模型输出的 JSON 做防御性解析——去除围栏、类型收窄、畸形输入给出可读错误而非页面崩溃。

两项外部工具能力补齐了纯文本模型的短板：联网检索让智能体获取实时、可溯源的外部信息，避免训练数据过时导致价格、场地、日期失真；文生图让系统不仅能「写」海报文案，还能直接「画」出海报图片，并支持基于上一版图片的图生图迭代——传统工作流中这一步需教师手动把文案翻译成文生图提示词，本作品自动完成衔接。

### 4.3 一条完整的用户与智能体交互任务流程

以「莫伊大学孔子学院策划一场中秋文化活动」为例，用户走完一条完整流水线：

1. **填简报**：填写活动名称、机构、日期、人数、预算、地点、目标人群、目的等基础信息。
2. **项目经理体检**：AI 检查简报完整性，指出「预算单位未明确」「日期未定」等阻塞项与次要提醒，教师补充后继续。
3. **资料调研**：AI 联网检索场地、当地活动参考、本地采购价格等信息，产出入库的研究条目与事实账本，每条事实带来源名称与链接，检索不到的价格标 UNKNOWN。
4. **方案生成**：AI 生成多个方向不同的候选方案（如游园会、文化工坊、文化展演 + 美食市集）。
5. **AI 评审**：评审智能体从目标人群匹配度、预算可行性、文化深度、执行难度、安全风险、可复制性等 8 个维度打分，指出优劣与风险并给出推荐。
6. **关卡 1 选方向**：教师点击选定一个方案，系统绝不自动选择。
7. **事实核验**：AI 抽取选中方案的外部事实（场地容量、设备、食材价格、当地规定等），逐一判定 FACT / USER_PROVIDED / ASSUMPTION / UNKNOWN / CONFLICT，教师对存疑事实点击「确认 / 驳回 / 补充说明」。
8. **并行产出**：基于选中方案依次生成 15 章节详细方案、10 类预算明细（每项标置信度）、多用途宣传文案、海报文案，并调用文生图生成海报初稿；对海报不满意可输入一句修改指令（如「换成夜晚灯笼背景」），基于上一版图片做图生图迭代、版本递增。
9. **发布质检**：QA 智能体核对日期、地点、预算合计、文案与海报等跨模块一致性，输出 PASS / WARNING / BLOCK。
10. **关卡 2 审批**：教师点击「批准 / 驳回 / 要求修改」，流程结束，产出含方案、预算、文案、海报图、质检报告的完整策划文档。

每一步产物都可编辑、可重新生成，落库带版本号与时间戳，重新生成版本递增、不覆盖旧版。

### 4.4 人机协同模式与创新之处

**人机协同模式**：AI 承担「重、专、多」的生成工作——方案设计、预算测算、文案撰写、海报制作、质检核对；人类承担「真、对、拍板」的决策工作——补充关键信息、选择方向、核验事实、最终审批。二者通过「数据自动落库 + 人工关卡强制」衔接，AI 全程只生成候选与建议，不替人做任何关键决定。这种边界把「办一场高质量活动」的门槛从「需要专业策划团队」降到「一名教师 + 一台电脑」，同时用架构守住「AI 不替人拍板、不编造事实」的底线——即使 AI 给出错误建议，两道人工关卡与事实核验也会拦住。

本作品的创新点有三：

1. **事实账本反幻觉机制**：把「不编造」从口号变成可执行机制——外部事实必须有来源；无来源显式标 UNKNOWN，推测标 ASSUMPTION，冲突保留双方原文，用户提供或人工核验通过标 USER_PROVIDED；人工核验结果只能由真人点击写入，AI 绝不代真人标注「已核验」。
2. **双重人工关卡架构固化**：在流水线嵌入「选方向」与「最终审批」两道必须真人点击的关卡，把「人主导、AI 辅助」固化为不可绕过的流程节点——没有人工点击，下游步骤无法启动。
3. **全流程单平台闭环**：从简报到审批在同一平台完成，数据自动流转，无需跨工具搬运；海报环节文案自动转文生图提示词并出图，基于上一版图片图生图迭代，教师无需离开平台重写提示词。

## 5. 知识图谱或语料库使用情况说明

本作品未接入国际中文教育知识图谱，也未预置固定语料库，采用「联网实时检索 + 项目内事实账本」方案，特此如实说明。

**一、未使用知识图谱的理由**。文化活动策划依赖的场地条件、采购价格、开放日期、机构规定等信息具有强时效性——报价会变、场地可用情况会变、当地规章会更新。预置知识图谱或语料库一旦形成即开始「过期」，在跨文化场景下反而可能比实时检索更危险（因为用户会误以为静态数据是准确的）。因此本作品选择以联网检索获取实时公开资料，换取信息的时效性与可核验性：每条事实均带来源链接，评委与用户可随时点击核验，这是静态语料库难以替代的。

**二、事实账本承担结构化知识管理职责**。虽未用知识图谱，本作品以「事实账本」实现「把知识管起来」的目标：资料调研智能体将检索结果抽取为「研究条目 + 事实」两类结构化数据落库；每条事实带来源名称与链接，并带 FACT / USER_PROVIDED / ASSUMPTION / UNKNOWN / CONFLICT 五类状态标记；无来源显式标 UNKNOWN、推测标 ASSUMPTION、冲突保留双方原文；人工核验后的结果只能由真人写入。这构成一套可追溯、可核验、可沉淀的结构化事实管理机制——它不预设领域知识，但保证进入方案的每一条事实都有出处、有状态、有人把关。

**三、接入规划**。本作品架构已为此预留路径：事实账本本身即「实体—属性—来源」的最小单元，未来可将账本事实映射到国际中文教育知识图谱（如节令习俗、文化专题、机构库）作为节点，形成「实时检索补充时效信息 + 知识图谱提供稳定领域知识」的双源融合；多个项目沉淀的历史事实亦可反哺机构自有小规模领域知识库。当前以「诚实标注 UNKNOWN + 来源可追溯」为底线，为后续接入保留开放接口。

## 6. 验证情况、效果证据与价值判断

**验证情况**：本作品已完成小范围试用——由海外孔子学院志愿者教师在真实筹备场景中试用，反馈良好（定性），但尚未开展规模化验证，也暂无量化效果数据，特此如实说明。

### （一）作品完成情况与试用背景

以下能力均已实现，可在本地完整跑通「创建项目 → 全流程 → 两道关卡 → 审批」：完整数据模型（覆盖简报、分析、研究条目、事实账本、方案、评审、决策、预算、文案、海报、海报图片、质检、审批等环节，每类产物独立成表并带版本与时间戳）；11 个智能体（提示词、解析、落库全部实现）；两道人工关卡（选方向与最终审批真实点击、决定落库）；全部面板 UI（可编辑、可重新生成、可查看历史版本）；统一 AI 网关（文本生成、文生图、联网检索，含错误分类与防御性解析）；模型配置界面与一键安装/启动脚本。

试用者为莫伊大学孔子学院志愿者教师，语言学专业背景，此前无独立策划文化活动经验，也未接受过活动策划或预算管理培训。其以本作品平台独立完成一场中秋文化活动从构思到方案产出的策划准备，全程在同一平台内完成，未借助其他 AI 工具或外部设计软件，产生的版本、决定与核验记录均在平台内留存。

### （二）自检证据

- **验证闸门全绿**：项目内置 `verify.sh` 验证闸门（TypeScript 类型检查 + ESLint + 生产构建）三连通过，无类型错误、无 lint 违规、生产构建成功。
- **全新环境实测**：以全新环境方式实测首次安装脚本，依赖安装、数据库初始化、配置引导完整跑通。
- **反幻觉规则可对应到实现**：提示词中的反幻觉规则、事实状态分类、防御性 JSON 解析均有对应代码实现，可在成果展示中逐一对照。

### （三）试用反馈（定性）

试用反馈整体良好，主要体现在三方面：

1. **反幻觉机制有效**：事实账本对外部事实按 FACT / USER_PROVIDED / ASSUMPTION / UNKNOWN / CONFLICT 五类分层标注，无来源的信息被显式标为 UNKNOWN 或 ASSUMPTION，冲突保留双方原文，教师据此判断哪些信息需实地核实，而非直接采信 AI 的「场地可用、价格合理」。
2. **海报衔接省心**：海报文案生成后自动转化为文生图提示词并出初稿，教师无需手动「翻译」提示词、无需跨工具调试，不满意时只需输入一句自然语言修改指令即可基于上一版图片迭代，版本自动递增。
3. **单平台闭环 + 发布质检**：简报是唯一输入源，后续每个智能体自动读取上游已落库数据，QA 环节自动核对日期、地点、预算、文案与海报等跨模块一致性，避免了多工具间手动搬运造成的低级不一致。

需要说明的是，以上反馈为定性结论，尚未收集到事实准确率、方案可用性等量化指标。

### （四）存在的不足

1. 试用样本小（单用户、单场景），尚未在春节、汉语角、招生宣传等其他活动类型中验证通用性；
2. 新手体验有待优化：首次使用需配置模型密钥，对非技术背景教师存在门槛；安装配置中的技术术语易造成困惑；AI 生成等待时缺乏时长提示；事实状态以英文缩写（UNKNOWN / CONFLICT 等）显示，一线教师不易理解；
3. 联网调研依赖外部搜索服务与网络环境，离线场景下研究库与事实账本为空，网络不稳定的海外站点需有降级方案；
4. 预算明细中的价格置信度目前依赖 AI 判断，尚未建立「当地实际采购价 → 回写更新预算」的闭环；
5. 尚未建立自动化测试体系（单元 / 集成 / 端到端测试在待办中）。

### （五）后续验证计划

1. 先在试用反馈基础上优化新手体验：将事实状态标记换成中文说明、补充生成等待的时长提示、简化首次密钥配置引导；
2. 在莫伊大学孔院后续活动（如春节文化周）中继续试用，检验多场景通用性；
3. 邀请更多孔院一线教师小范围试用，收集「方案可用性、事实准确率、操作易用性」三方面反馈并逐步量化；
4. 逐步补建自动化测试体系，覆盖 Provider 层、各智能体解析器与端到端全流程。

**价值判断**：本作品的价值不在于「生成一篇漂亮文案」，而在于把「AI 辅助活动策划」这个高频、真实、且有明确质量风险（幻觉、跨工具断裂、经验无法沉淀）的任务，落成一套可追溯、有人把关、可复制、可交接的工程方案。在海外中文教学机构人手少、经费紧、教师流动大的现实条件下，它让文化传播使命不再依赖个别老教师的个人能力与经验，而是成为一名新任教师独立即可交付的标准化产出——这正是国际中文教育在海外可持续发展所急需的基础能力。

## 7. 其他补充说明（选填）

- 本项目以本地运行方式发布：用户下载解压后，双击「首次安装脚本」与「启动脚本」即可使用，无需编程背景，也无需自行配置开发环境。

- 试用场景的方案数据可应评委要求提供完整演示。
