# 部署到公网（评委可直接访问的链接）

> 目标：把「小莫」放到一个公网地址上，评委点开就能用，不需要安装任何东西。
> 本项目是 **Next.js 服务端应用 + SQLite 文件数据库**，因此只能部署到**带可写磁盘的容器 / 服务器**，不能用纯静态托管（Vercel、GitHub Pages、Netlify 静态站点都不行）。

部署后由管理员预先填好模型 Key，访客打开链接即可直接使用；模型配置页会自动锁定（`EP_PUBLIC_MODE=1`），防止访客改写模型地址劫持 API Key。

---

## 方案 A：Render 免费档（推荐，免绑卡）

**代价**：15 分钟无访问会休眠，冷启动约 1 分钟；休眠 / 重新部署会清空 SQLite 数据（表结构自动重建）。

1. 用 GitHub 账号登录 <https://render.com>，选择 Free 计划（不需要信用卡）。
2. 右上角 **New → Blueprint**，选中 `Joey1444/ai-event-assistant` 仓库。
   Render 会自动读取仓库里的 `render.yaml`，把构建命令、启动命令、环境变量全部填好。
3. 部署时它会让你补填三项**没有写进仓库**的值：
   - `EP_AI_API_KEY`：DeepSeek 的 Key
   - `EP_IMAGE_API_BASE_URL`：通义万相地址，形如 `https://maas.qianwenaiapi.com/api/v1`
   - `EP_IMAGE_API_KEY`：通义万相的 Key
   - `EP_TAVILY_API_KEY`：Tavily 的 Key（不填则资料调研不可用，其余功能正常）
4. 点 **Apply / Deploy**，等待首次构建（约 3~5 分钟）。
5. 拿到地址 `https://ai-event-assistant-xxxx.onrender.com`，发给评委即可。

**可选但强烈建议**：用 [UptimeRobot](https://uptimerobot.com) 或 [cron-job.org](https://cron-job.org) 每 5 分钟访问一次首页，避免休眠导致的冷启动等待和数据清空（免费额度每月 750 小时，够覆盖 744 小时）。

> 若不想用 `render.yaml`，也可以在 Render 手动建 Web Service，填：
> Build `npm ci && npx prisma generate && npm run build`；
> Start `npx prisma db push --skip-generate && npm run start`；
> 环境变量照 `render.yaml` 抄一遍。

## 方案 B：Railway（数据可持久，需要绑卡）

**代价**：试用额度 $5 / 30 天（免卡），之后 $5/月。好处是有 **0.5GB 持久卷**，项目数据不会丢。

1. GitHub 登录 <https://railway.com> → **New Project → Deploy from GitHub repo**。
2. 添加一个 **Volume**，挂载到 `/app/data`。
3. 环境变量：
   - `EP_DATABASE_URL=file:/app/data/prod.db`
   - `EP_PUBLIC_MODE=1`
   - `EP_AI_BASE_URL` / `EP_AI_MODEL` / `EP_AI_API_KEY`
   - `EP_IMAGE_API_BASE_URL` / `EP_IMAGE_MODEL` / `EP_IMAGE_API_KEY` / `EP_IMAGE_TIMEOUT_MS`
   - `EP_TAVILY_API_KEY`
   - `EP_DAILY_CALL_LIMIT=300`
4. Railway 会自动识别仓库里的 `Dockerfile` 并构建；启动时自动执行 `prisma db push` 建表。
5. 在 Settings → Networking 里 **Generate Domain** 得到公网地址。

## 方案 C：自己的服务器 / VPS（最稳定）

```bash
git clone https://github.com/Joey1444/ai-event-assistant.git
cd ai-event-assistant
docker build -t ai-event-assistant .

docker run -d --name xiaomo -p 3000:3000 \
  -v aes-data:/app/data \
  -e EP_PUBLIC_MODE=1 \
  -e EP_AI_BASE_URL=https://api.deepseek.com \
  -e EP_AI_MODEL=deepseek-v4-pro \
  -e EP_AI_API_KEY=你的key \
  -e EP_IMAGE_API_BASE_URL=你的文生图地址 \
  -e EP_IMAGE_API_KEY=你的key \
  -e EP_IMAGE_MODEL=wan2.7-image-pro \
  ai-event-assistant
```

前面套一层 Nginx / Caddy 反向代理 + HTTPS 即可对外。国内云服务器（阿里云、腾讯云）对评委访问最稳，但默认域名需要备案才能用 80/443。

## 方案 D：本机 + 临时隧道（无需任何账号，但要一直开机）

适合「评审当天临时演示」：

```bash
set EP_PUBLIC_MODE=1
npm run build
npm start
```

另开一个窗口，用临时隧道把本机 3000 端口暴露出去：

```bash
cloudflared tunnel --url http://localhost:3000
```

终端会打印一个 `https://xxxx.trycloudflare.com` 地址，有效期到进程退出——电脑休眠、关机、断网都会让链接失效，**不适合作为正式提交的链接**。

## 部署前须知

- **数据会重置**：Render 免费档休眠或重新部署会清空 SQLite。评委各自创建的项目互不影响，但不会长期保留。
- **费用**：走的是你预先配置的模型 Key，一个完整策划约 1.5 元。`EP_DAILY_CALL_LIMIT` 限制的是**进程内每日模型调用次数**（默认 300 次 ≈ 20 多次完整策划），防止链接被转发后刷爆；需要放宽或收紧就改这个值。
- **中国大陆访问**：Render / Railway 等国际平台在中国大陆可访问性不稳定，建议提前自测；如评审主要在国内，优先考虑方案 C 的国内云服务器。
- **不要把 Key 写进仓库**：三项密钥只在平台的环境变量里填。
