## 1. 项目概述

面向新手的 AI 活动策划工具，用「**AI 提议 + 人类决定**」的方式，把一次活动从需求分析一路推进到最终审批。AI 全程只产出候选与建议，拍板只由真人点击完成。

- 技术栈：Next.js 16（App Router）+ TypeScript + Tailwind CSS 4；Prisma 6 + SQLite。
- AI 接入：文本直连 DeepSeek 官方 API、文生图直连第三方 DashScope 原生 API、联网检索走 Tavily（统一入口见 [lib/ai/provider.ts](../lib/ai/provider.ts)）。
- 首个实战场景：莫伊大学孔子学院中秋节活动策划。

## 2. 架构分层

```
app/         路由页面：首页项目列表、projects/new|edit|[id]|[id]/approve、ai-test
components/  ui/（Button/Card/Section/Field/Badge 原语）
             agents/（各 Agent 面板，客户端组件）
             projects/（表单/步骤条/删除/下一步条）
lib/         ai/（Provider 抽象 + 配置 + Tavily）
             agents/（Agent 实现 + action + registry + format + parse + types）
             serializers.ts · db.ts · status.ts · actions.ts
             env.ts · workflow.ts · steps.ts · validation.ts
prisma/      schema.prisma（数据模型唯一来源）+ dev.db（SQLite，gitignore）
```

分层原则：

- **AI 唯一入口**：业务代码与 Agent 一律走 `lib/ai/provider.ts` 的 `generateText()` / `generateImage()`，禁止直接 fetch 模型端点，换模型只改配置。
- **Agent 四层分离**（见下节）。
- **序列化统一**：DB 行 → 前端对象的转换只在 `lib/serializers.ts`，页面不重复写 `toXxx`。

## 3. 核心抽象

### 3.1 AI Provider 层（`lib/ai/provider.ts`）

- `generateText()`：直连 DeepSeek（OpenAI 兼容 `/chat/completions`），统一 `AiError`（network/http/timeout/truncated/unknown）+ `classifyError()` 译成人话。
- `generateImage()`：直连 DashScope 原生 API，`input.messages.content` 数组承载参考图（多图生图），非本机强制 https；返回图片过魔数校验，只放行 png/jpeg/webp、拒 svg、限 8MB。
- 配置在 `lib/ai/config.ts`，`getAiConfig()` / `getImageConfig()` **每次动态读** `process.env`（不缓存），让「写 `.env` 后立即生效」成立。

### 3.2 Agent 四层

```
components/agents/<Name>Panel.tsx   （"use client"，useTransition 调 action，展示结果）
        ↓ 调用服务端 action
lib/agents/actions.ts               （"use server"：读库 → 调 agent → 落库 → 返回可序列化结果）
        ↓ 调用纯函数
lib/agents/<name>.ts  runXxx()      （只写 prompt + JSON 解析，输入 → generateText → 结构化数据）
        ↑ 元数据来源
lib/agents/registry.ts              （Agent 清单的单一事实来源）
```

- 纯函数层不碰库、不碰 UI，只关心「给什么输入、返回什么结构」。
- action 层负责「读哪些表 → 写哪张表」（见 `lib/agents/actions.ts` 各函数的 `include` 与 `$transaction`）。
- 面板层只负责「按钮 + 调 action + 展示」，加载态用 `isPending`。

### 3.3 配套模块

- `lib/agents/format.ts`：DB 行 → Agent 输入文本（`formatBrief` / `formatResearch` / `formatFacts` / `formatConceptText` / `formatPlanText` 等）。
- `lib/agents/parse.ts`：防御性 JSON 解析（去围栏、`toStrArray` / `toBool` / `toNumber` 收窄），畸形 JSON 给可读错误、不崩页面。
- `lib/serializers.ts`：DB 行 → 前端数据对象统一转换。
- `lib/workflow.ts`：`getNextAction()` 纯函数，按「数据是否已产出」推导「下一步」，非状态机驱动。
- `lib/steps.ts`：步骤序号 / 标签 / 锚点单一来源，侧边栏 `WorkflowStepper` 与面板标题 `StepHeading` 共用。
- `lib/status.ts`：项目状态常量 + 中文标签 + 色调。

## 4. 数据模型

表与字段唯一来源是 `prisma/schema.prisma`，这里只写结构与原则：

- **扁平单枢纽**：`Project` 为根，其余子表以 `projectId` 外键挂接、全部 `onDelete: Cascade`；`ProjectBrief` 用 `@unique projectId` 实现一对一。
- **唯一二级一对多**：`Budget` → `BudgetItem`（经 `budgetId`，不直接挂 project）。
- **版本表模式**：方案 / 预算 / 文案 / 海报 / 海报图 / Final QA 同构——`version + createdByAgent`，重新生成不覆盖旧版，靠 `nextXxxVersion()` 取 max+1 递增保历史。
- **软引用而非外键**：`Decision.selectedConcept` 存 variant 字符串（A/B/C，Reject All 为 null）；`PosterImage.parentVersion` 存父图版本号，图生图迭代靠它回溯。

### 状态机

- **Project.status**：常量见 `lib/status.ts`；但真实推进不由状态机驱动，而由 `getNextAction()` 按「数据是否产出」判定。状态仅在三处 action 被写入：分析→PM_ANALYSIS、选方向→HUMAN_DECISION_COMPLETED、审批→APPROVED/REJECTED/REVISION_REQUIRED。
- **Fact 状态机**：AI 只能写到 UNKNOWN / CONFLICT / ASSUMPTION / FACT；`checkedAt` 区分两类事实——调研事实为空（`researchProject` 写）、核验事实非空（`factCheckProject` 写）。人工核验 `verifyFact` 唯一写 `verification` / `humanNote`，仅 verified 时把 status 抬到 USER_PROVIDED——**AI 绝不代真人落「已核验」**。

## 5. 数据流

### 5.1 流水线全貌

顺序以 `lib/agents/registry.ts` 的 `AGENTS` 数组为准：

```
简报 → PM → Researcher → Strategist → Critic → 🧑 Gate1 选方向
     → FactChecker → Planner → Budget/Copy/Poster → PosterDesigner → QA → 🧑 Gate2 审批
```

每步「读哪些表 → 写哪张表」以 `lib/agents/actions.ts` 各 action 的 `include`（读）与 `$transaction`（写）为准：

- 前三步读 brief（+research/facts），产 PmAnalysis / ResearchItem+Fact / Concept。
- 依赖 Gate1 的步骤（FactChecker / Planner）先取 `decisions[0]?.selectedConcept` 定位 variant，再回 concepts 找对象。
- 依赖详细方案的步骤（Budget / Copy / Poster / QA）读 `plans[0]`（最新版本），各产版本表。

### 5.2 提示词数据流

- **DB → prompt 文本**集中在 `lib/agents/format.ts`。
- **输入模式**：简报第一 + 研究 + 事实 + 方案；`runXxx()` 输出解析为结构化 JSON，action 落库——JSON 一律 `JSON.stringify` 存文本列，读回由 `formatXxx` 里 `JSON.parse` 还原。

## 6. AI 网关与配置

### 6.1 网关

- 文本 `generateText()`、文生图 `generateImage()`，见 `lib/ai/provider.ts`（错误分类、图片魔数校验、https 强制都在这里）。
- 配置 `getAiConfig()` / `getImageConfig()` 每次动态读 `process.env`，见 `lib/ai/config.ts`。

### 6.2 配置管理

- `lib/env.ts` 的 `upsertEnv()` 原子写 `.env`（临时文件 + rename）：更新已有 key、追加新 key、保留注释/空行，值含 `#` / 空格 / 引号 / 换行时双引号转义防注入；`maskKey()` 只回「****末4位」。
- `/ai-test` 页面 + `components/AiConfigForm.tsx`：配置文本 / 文生图的 baseURL / model / apiKey，留空即不修改；`saveAiConfig` 经 Zod 校验，key 只回掩码不回明文。

## 7. 提示词工程

全部 Agent 的实现见 `lib/agents/*.ts`，清单见 `lib/agents/registry.ts`。

- **统一骨架**：XML 六段式 `<角色>/<任务>/<输出>/<规则>`（复杂 Agent 加 `<思考>`，少数加 `<示例>`）；静态指令进 system、动态输入进 user，命中前缀缓存省 token。
- **反幻觉四件套**：绝不编造 / 允许说 UNKNOWN / 区分事实与推测 / CONFLICT 保留双方原文。
- **事实可信度分层**：USER_PROVIDED（含已人工核验）与 FACT 可信直接使用；ASSUMPTION 使用要标注；UNKNOWN 与 CONFLICT 不能当确定事实、使用处标 `[待确认]`。
- 完整铁律见 `rules/AI_DEVELOPMENT_RULES.md`（唯一权威）。

## 8. Human Gate

两道必须真人点击的关卡，AI 只提议不拍板：

- **Gate1 选方向**：`selectConcept()` 落 `Decision`（selectedBy="user"）。
- **Gate2 最终审批**：`submitApproval()` 落 `Approval`（APPROVED / REJECTED / REVISION_REQUIRED，Zod 校验）。

每个决定都落库，并成为后续步骤的输入。

## 9. 发布与运行

- `setup.bat`（首次安装五步）：Node 20.9+ 检查 → 复制 `.env` → `npm ci` → `prisma generate` → `prisma db push`。
- `start-share.bat`（一键启动）：先停旧 dev server → `prisma generate` → `npm run dev`。
- `build-release.bat`（打包）：用 Windows 自带 `bsdtar` 打 zip，排除 node_modules / .next / .env / *.db 等。
- 验证闸门 `verify.sh` = `tsc --noEmit` + `eslint` + `next build` 三连，全绿才算完成。
- 环境要求 Node ≥20.9；依赖锁定用 `package-lock.json`。
