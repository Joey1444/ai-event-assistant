# 数据模型与生成影响（技术文档底稿）

> 本文是当前数据模型的**完整快照**，供撰写技术文档参考。
> 表名、字段、默认值以 `prisma/schema.prisma` 为准；每一步「读哪些表 → 写哪张表」以 `lib/agents/actions.ts` 为准。本文与代码冲突时，以代码为准。

## 一、表关系总览（16 张表）

所有表都通过 `projectId` 外键挂在 `Project` 下（`onDelete: Cascade`），只有 `Budget → BudgetItem` 是二级一对多。

```
Project（项目主表：projectName / organization / status）
│
├─ ProjectBrief   1:1   项目简报（eventType/eventDate/budget/location/objective/…）
├─ PmAnalysis     1:N   PM 分析结果（summary/blockers/canStart/…）
├─ ResearchItem   1:N   研究资料库（title/content/source/sourceUrl）
├─ Fact           1:N   事实账本 ★（claim/status/requiresHumanVerification/…）
├─ Concept        1:N   活动方案 A/B/C（variant/direction/content）
├─ Critique       1:N   评审结果（scores/strengths/risks/recommendedConcept/…）
├─ Decision       1:N   人工选择方向 ★（selectedConcept/rejected/decisionNote）
├─ ActivityPlan   1:N   详细方案（version/content/createdByAgent）
├─ Budget         1:N   预算（version/currency/contingencyRate/summary/costRisks）
│   └─ BudgetItem 1:N   预算明细（category/item/quantity/unit/unitPrice/source/confidence）
├─ Copy           1:N   宣传文案（version/content/createdByAgent）
├─ Poster         1:N   海报文案（version/content/createdByAgent）
├─ PosterImage    1:N   海报图片（version/imageDataUrl/prompt/parentVersion）
├─ FinalQa        1:N   发布前检查（version/result/summary/findings）
└─ Approval       1:N   最终审批（decision/approvalNote/approvedAt）
```

**两处软引用（无外键，靠字段值关联）：**

- `Decision.selectedConcept` → `Concept.variant`（字符串 "A"/"B"/"C"）。重新生成方案会清空 Decision，避免软引用失效。
- `PosterImage.parentVersion` → 上一版 `PosterImage.version`（图生图版本链）。

**Fact 表双重身份（同一张表两类事实，靠 `checkedAt` 区分）：**

| | 调研事实（Researcher 写） | 核验事实（FactChecker 写） |
|---|---|---|
| `checkedAt` | `null` | 时间戳 |
| 含义 | 联网调研到的外部事实 | 对所选方案核验后的事实 |
| `verification`/`humanNote` | 空 | 人工确认后填 verified/rejected + 备注 |

## 二、生成数据流（表 → Agent → 落库）

数据库行 → 提示词文本的桥接都在 `lib/agents/format.ts`。流水线顺序与 Agent 元数据见 `lib/agents/registry.ts`。

| # | 步骤 | 读取的表（进提示词） | 写出的表 |
|---|---|---|---|
| 1 | PM 分析 | Project + ProjectBrief | PmAnalysis |
| 2 | 资料调研 | ProjectBrief（+ Tavily 联网检索） | ResearchItem + Fact(调研) |
| 3 | 活动方案 | ProjectBrief + ResearchItem + Fact(调研) | Concept |
| 4 | 小莫评审 | ProjectBrief + ResearchItem + Fact(调研) + Concept(3个) | Critique |
| 5 | 选择方向 | （人工点击，无 AI 提示词） | Decision |
| 6 | 事实核验 | ProjectBrief + Concept(仅选中) + ResearchItem + Fact(调研) | Fact(核验) |
| 7 | 详细方案 | Decision→Concept(选中) + ProjectBrief + ResearchItem + Fact | ActivityPlan |
| 8 | 预算 | ActivityPlan + ProjectBrief + ResearchItem + Fact | Budget + BudgetItem |
| 9 | 文案 | ActivityPlan + ProjectBrief + ResearchItem + Fact | Copy |
| 10 | 海报 | ① 文案：ActivityPlan+ProjectBrief+ResearchItem+Fact → Poster；② 图：Poster(文案)+ProjectBrief → PosterImage | Poster + PosterImage |
| 11 | 发布前检查 | ProjectBrief+ResearchItem+Fact+Concept(选中)+ActivityPlan+Budget(+明细)+Copy+Poster | FinalQa |
| 12 | 最终审批 | （人工点击） | Approval |

## 三、桥接函数（DB 行 → 提示词文本）

| 函数（`lib/agents/format.ts`） | 输入的表 | 作用 |
|---|---|---|
| `formatBrief` | Project + ProjectBrief | 拼出 9 个简报字段（每个 Agent 的提示词都先塞这个） |
| `formatResearch` | ResearchItem[] | 拼研究条目（标题/内容/来源） |
| `formatFacts` | Fact[] | 拼事实账本（claim + status + source） |
| `formatConceptsText` / `formatConceptText` | Concept[] / Concept | JSON.parse 后拼方案字段 |
| `formatPlanText` | ActivityPlan | JSON.parse 后拼 16 章节方案 |
| `formatBudgetForQa` | Budget + BudgetItem[] | 拼预算摘要 + 明细 |
| `formatContentForQa` | Copy / Poster 的 content | JSON.parse 后拼文案/海报文案 |

## 四、对生成的关键影响（结构约定）

1. **ProjectBrief 是唯一贯穿全链路的输入**：改简报字段 → 所有 Agent 的提示词都变。
2. **Fact 是双写的**：调研事实（`checkedAt=null`）与核验事实（`checkedAt≠null`）都在 Fact 表，`formatFacts` 会把两种都拼进下游提示词。核验事实里的 `UNKNOWN/CONFLICT` 状态会作为风险信号透传给方案/预算/文案/QA。
3. **Decision 是硬闸门**：第 6 步事实核验和第 7 步详细方案都要求先有 `Decision.selectedConcept`，否则报「还没选择方向」。选方向后，下游提示词里的方案从「三个」收窄成「选中」。
4. **版本表模式**：ActivityPlan/Budget/Copy/Poster/PosterImage 都带 `version` + `createdByAgent`，action 一律 `orderBy version desc` 取最新版喂提示词；历史版只在前端做对比，不进提示词。
5. **人工关卡**：两道硬关卡（选方向 Decision、最终审批 Approval）只能人工点击产生；事实核验是软提醒（「下一步」提示还有 N 条待核验，但不阻断下游）。
