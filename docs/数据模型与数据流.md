# 数据模型与数据流（架构文档）

本文档只写**不变的结构与原则**。具体有哪些表、每张表有哪些字段、字段默认值，一律以 `prisma/schema.prisma` 为准；每步「读哪些表 → 写哪张表」以 `lib/agents/actions.ts` + `lib/agents/format.ts` 为准。

## 一、结构：单枢纽 + 扁平

- 一张主表是唯一枢纽，其余表都通过 `projectId` 外键挂到它下面（级联删除）。
- 只有一处二级「一对多」：预算主表挂预算明细子表。
- 除此之外没有跨表外键，都是「主表 1—N 子表」的扁平结构。

> 完整表清单与字段：`prisma/schema.prisma`。

## 二、四类关键约定（稳定不变）

1. **简报是唯一贯穿输入**：项目详情（一对一挂在主表下）会被每个 Agent 的 prompt 第一个拼接。
2. **事实账本的双重身份**：同一张事实表承载两类事实——调研事实（`checkedAt` 为空）与核验事实（`checkedAt` 非空）；人工核验结果（`verification` / `humanNote`）只能由人工动作写入，AI 不得碰。
3. **版本表模式**：方案 / 预算 / 文案 / 海报文案 / 海报图片都带 `version` + `createdByAgent`，action 一律取最新版喂 prompt，历史版只在前端做对比。
4. **软引用**：选方向用 variant 字符串关联方案；海报图片用版本号关联上一版。这是无外键的弱关联——重新生成方案会清空旧决策，避免软引用静默失效。

## 三、提示词数据流（DB → prompt → 落库）

- 所有「DB 行 → 提示词文本」的转换集中在 `lib/agents/format.ts`（`formatBrief` / `formatResearch` / `formatFacts` / `formatConceptsText` / `formatPlanText` / `formatBudgetForQa` / `formatContentForQa`）。
- 每个 Agent 的 action 在 `lib/agents/actions.ts`：读库 → 调 agent（喂 format 后的文本）→ 落库。具体每步读哪些表、写哪张表，看各函数的 `include` 与 `$transaction`。

## 四、数据流的闸门（不变的原则）

- 两道硬关卡：选方向、最终审批，只能由人工点击产生，AI 不参与。
- 事实核验是**软提醒**：核验事实里有「待人工核验」且未处理的，引导会提示，但不阻断下游生成。

## 五、找详情的入口

- 表结构与字段：`prisma/schema.prisma`
- 流水线顺序 + 元数据：`lib/agents/registry.ts`
- 每步读写的表：`lib/agents/actions.ts`
- DB → prompt 序列化：`lib/agents/format.ts`
- DB → 前端对象：`lib/serializers.ts`
